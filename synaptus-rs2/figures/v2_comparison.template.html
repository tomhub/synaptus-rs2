Chasing the fourth digit

We read the papers, found two ways to compute phase shift migration more exactly, and wrote Synaptus in Rust a second time. It worked. Then we put every error we measured on one ruler, including the one we cannot fix with arithmetic.

Three papers and a substitution

What v2 changes

In 2011 the MULOK paper called an interpolation-free mapping from frequency to depth "a subject for future work". A good nonuniform FFT library appeared in 2019. We are fashionably late, and we kept v1 untouched next to v2 so nobody has to take our word for it.

A · NUFFT-PSM

The same sum, without the slow loop

Phase shift migration adds up frequency samples once for every depth. For layered media that sum is exactly a nonuniform Fourier transform, so a NUFFT evaluates it with no interpolation and no Jacobian. It matches v1 to . The MULOK defects found in v1 have nothing to attach to.

Barnett, Magland & af Klinteberg, SIAM J. Sci. Comput. 41 (2019). Skjelvareid et al., IEEE TUFFC 58 (2011).
B · SQ-PSM

The integral that PSM approximates

PSM's frequency sum is a rectangle rule, so its error shrinks only like 1/m as the time record is padded m-fold. After substituting ω = ω* + s² the integrand has no branch point, and Gauss–Legendre converges geometrically. A second NUFFT supplies the spectrum at the nodes. Our own derivation; we found no paper doing this for migration.

Trefethen, SIAM Rev. 50 (2008), Thm 4.5. Dossier §5.

Padding is not a plan

More zeros help, mostly

v1 PSM with the time record padded m-fold, against the limit. All three datasets fall roughly like 1/m, which is what a rectangle rule with misaligned band edges predicts. Twice, doubling the padding made things worse: pins from 4× to 8×, plane from 8× to 16×. The band edges land on the frequency grid differently each time, so there is no reliable rate to extrapolate.

Bugs, switched off

The original's bugs no longer run by default

Both Rust versions keep a faithful copy of the original code, bugs and all, under legacy::, because you cannot measure a fix without the thing it fixes. Nothing calls those copies unless you ask for them by name. Everything else, including every default, runs the corrected algorithms.

raccoon

The raccoon went through the original's frequency bins, as raccoons do with bins, and found a Stolt factor applied twice, a depth grid missing its bottom end, and a frequency axis labelled ¾ of a bin off. In the cylindrical code it found a 64° arc treated as a full circle, evanescent waves let in with zero phase, and a DC bin nobody asked for.

badger

The badger points out that fixing CPSM did not make it visibly sharper: on synthetic scatterers, old and new both land within half a sample. The fix buys correctness, not a makeover. The full gallery, with the thesis figures alongside, is in synaptus-rs2/FIGURES.md.

Things that went wrong

The parts we would rather not mention

  • our bug

    Our own node count forgot the time delay

    The quadrature rule assumed the integrand oscillates no faster than the FFT period allows. The delay before the first sample adds its own oscillation, and in shallow layers nothing cancels it. Our self-convergence test caught it on synthetic data: the shallow layer passed by a hair. Fixed as amendment A2. The run before the fix is kept.

  • inconclusive

    The referee needed extra time

    The independent Python oracle agreed with SQ-PSM at 21 of 24 pixels on the first try. At the other 3 the oracle itself had not converged, so those are recorded as inconclusive, not passed. A finer oracle, run as a separately labelled follow-up, then agreed at .

  • v1's ruler

    v1 graded itself with a bent ruler

    v1 measured its accuracy against PSM with 8× padding. That reference turns out to sit from the limit. The v1 conclusions survive, but some of its decimals do not: accurate MULOK is from the limit, not the 4.7e-4 v1 reported for pins.

  • same author

    The oracle and the method share a parent

    The oracle uses a different quadrature, no substitution and no NUFFT, but the same person wrote both, from the same definition. A shared misreading of that definition would slip through. That NUFFT-PSM matches v1, which matches the original Octave code, and that padded PSM converges to SQ-PSM, both argue against it. Neither proves it.

  • anticlimax

    We fixed four things in CPSM and the picture barely moved

    Integer angular orders, no evanescent leak, no DC bin, a transfer function that agrees with the thesis' own asymptotics. The pipe image's brightness changes by and almost nothing moves. Correct and boring beats wrong and exciting, but it makes for a poor trailer.

  • untested

    3D got less scrutiny

    SQ-PSM in 3D (the plane scan) is checked only by the convergence test and the scoreboard, not by the pixel oracle.

The elephant

The arithmetic is now far better than the physics

≈ 6%

The MULOK paper notes that transmission through an interface depends on angle, varying by about 6% across the beam in its copper example. PSM and MULOK treat it as constant. They also assume scalar waves, no attenuation and an exploding reflector. SQ-PSM agrees with itself to about a model that may be wrong in its second digit on real specimens. We have not measured how wrong on these datasets. That is the next honest piece of work, and no amount of Gauss–Legendre will do it. The badger and the raccoon have both tried pushing the elephant. It did not move.
